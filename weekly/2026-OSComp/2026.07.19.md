**详细工作日志如下：**

1. trace 入口函数的设计理由：

- **启动追踪链。**因为调试器的跟踪原理是在poll函数进入/退出安装断点，通过手动设置入口函数，从而当其命中时给其中调用的poll函数安装断点，启动整个追踪链；
- **过滤噪音。**一个异步程序里可能有几十上百个并发的协程实例，如果对所有白名单里的 poll 函数都装 PollEntryBP，栈里会混入大量不关心的协程。trace root 的作用就是划定边界："我们只关心从这个函数开始的调用链。”

5. 由于async-os并没有复现成功，所以想先尝试适配rel4，写了第一版的调试配置文档，因为rel4是微内核，不涉及特权级切换，所以想先看看内核态的异步函数是否能够成功跟踪。

	现象：生成的白名单并没有异步函数

	暂时未找到原因，

	  - kernel.elf 原本是没有任何 async_fn 或 ::poll 状态机函数，通过--whole-archive 链接之后有了异步函数，但是没有poll函数；
	  - .a 和 .o 中：都没有编译器为异步函数生成的 Future 状态机 poll 函数，只有异步函数

	看了一下rel4的异步代码，终于弄明白了原因：

	**rel4 的异步系统调用依赖"用户态中断控制器（UINTC）"这个自定义硬件，它被做成可选开关，默认关闭：**

	![image-20260719031732305](https://p.ipic.vip/7mi4kh.png)

	```rust
	// rel4 的 src/lib.rs 里有这么三行：
	#[cfg(feature = "ENABLE_UINTC")]   // 只有开了 ENABLE_UINTC 开关才编译下面这行
	mod async_runtime;                  // 整个异步运行时：async_syscall_handler、executor、协程，全在这个模块里
	```

	使用`cargo build --release --target riscv64imac-unknown-none-elf --features "ENABLE_UINTC board_qemu"` 或者`./build.py -u`进行编译就行。

	验证过，确实就有poll函数了。不过编译会报错，rel4的这部分代码有bug，对相应部分打了补丁，成功编译。开始尝试调试。结果发现自己rel4的硬件部分没有跑通，看了官方文档，大概有方向了。
