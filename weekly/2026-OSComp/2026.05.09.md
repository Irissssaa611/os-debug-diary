1. 解决一些严重的明显问题：

我重新按照OS调试逻辑链梳理了一下代码，找到了如下几个问题（attach → QEMU → GDB → 状态机 → 断点组切换）：

- 问题 1：handleBreakpointHit 在 OS 模式下无条件发送 StoppedEvent

  handleBreakpointHit 总是发送 StoppedEvent。但在 border 断点和 hook 断点命中时应该是透明的（不应暂停 UI），状态机应该自动  continue。

- 问题 2：doAction 中的异步操作与状态机的同步执行冲突

  状态机在 kernel 状态收到 STOPPED 事件时，会产生两个 action：

a. try_get_next_breakpoint_group_name

b. check_if_kernel_to_user_border_yet

  这两个 action 都是异步的（内部用 .then()），但 forEach 是同步遍历的。这意味着：
  - 两个 action 同时发起异步操作（getStack），互相竞争
  - try_get_next_breakpoint_group_name 中的 eval(hook.behavior)() 返回 Promise，其 .then() 可能在 check_if_kernel_to_user_border_yet 已经触发了新的状态转换之后才执行
  - 如果 check_if_kernel_to_user_border_yet 先完成并触发了 AT_KERNEL_TO_USER_BORDER，状态已经变了，但 try_get_next_breakpoint_group_name 的回调还在用旧状态的假设执行

	这是最终准备落地的 getStringVariable：

	```rust
	  public async getStringVariable(name: string): Promise<string> {
	      if (!this.miDebugger) return '';
	      try {
	          // 1) 读 len
	          const lenRes = await this.miDebugger.sendCommand(
	              `data-evaluate-expression ${name}.vec.len`
	          );
	          const len = parseInt((lenRes.result('value') || '').trim(), 10);
	          if (!Number.isFinite(len) || len <= 0 || len > 4096) {
	              this.showInfo(`getStringVariable('${name}'): bad len`);
	              return '';
	          }
	
	          // 2) 读数据指针
	          const ptrRes = await this.miDebugger.sendCommand(
	              `data-evaluate-expression ${name}.vec.buf.ptr.pointer.pointer`
	          );
	          const ptrStr = ptrRes.result('value') || '';
	          const m = /0x[0-9a-fA-F]+/.exec(ptrStr);
	          if (!m) {
	              this.showInfo(`getStringVariable('${name}'): no addr`);
	              return '';
	          }
	          const addr = m[0];
	
	          // 3) 语言无关地按地址读 N 字节
	          const memRes = await this.miDebugger.sendCommand(
	              `data-read-memory-bytes ${addr} ${len}`
	          );
	          const contents: string = memRes.result('memory[0].contents') || '';
	          if (!contents) {
	              this.showInfo(`getStringVariable('${name}'): empty memory`);
	              return '';
	          }
	
	          // 4) hex → string
	          let out = '';
	          for (let i = 0; i + 1 < contents.length; i += 2) {
	              out += String.fromCharCode(parseInt(contents.substr(i, 2), 16));
	          }
	          this.showInfo(`getStringVariable got: ${out}`);
	          return out;
	      } catch (e: any) {
	          this.showInfo(`getStringVariable('${name}') failed: ${e?.message ?? e}`);
	          return '';
	      }
	  }
	```
	这个实现绑定 Rust String 内部布局（.vec.buf.ptr.pointer.pointer + .vec.len）。如果以后 rustc 改了字段路径就失效。成功了：
