适配过程中遇到的详细问题：

1. ###### 白名单生成为空

调试器连接后白名单生成失败，什么都没有。之前在 最新版上也遇到过一次同样问题，当时加 `-g` 就解决了，但这次不一样。

**排查过程**：

1. 首先确认 `-g` 有没有传进去。ELF 从 1.4M 涨到了 6.3M，说明 `-g` 确实生效了，符号表有内容。
2. 但 `readelf -S | grep debug` 看不到 debug sections，GDB 的 `info functions` 输出仍然是 `Non-debugging symbols:` 格式，没有 `File <路径>:` 和行号。
3. 用 `make V=1` 看实际的 rustc 命令行：**`-C strip=debuginfo`**——这是 Rust release profile 的默认行为，编译器在链接之后把调试信息又删掉了。

**根本原因**：Rust release 模式默认 `strip = "debuginfo"`。即使传了 `-g`，cargo 也会在最后一步把 debuginfo strip 掉。

**解决**：在 RUSTFLAGS 中加 `-C strip=none`，明确禁止 strip。最终的编译指令：

```bash
make build ARCH=riscv64 BLK=y NET=y A=apps/user_boot \
RUSTFLAGS="-C link-arg=-T/home/iristseng/data/async-os-original/linker_riscv64-qemu-virt.lds -C link-arg=-no-pie -C force-frame-pointers=yes -g -C strip=none"
```

NOTE：必须通过 `make` 的命令行传 RUSTFLAGS，不能用 `export` 环境变量——因为 Makefile 里的 `RUSTFLAGS := ...` 会覆盖环境变量，但命令行传参会覆盖 Makefile 赋值。

2. ###### 特权级切换的跟踪逻辑并没有生效

调试调试器，发现调试器并没有走任何特全级切换的调试逻辑，应该是边界断点未生效。实际检查，确实是边界断点只存入了调试器，但是并没有在GDB设置实际的断点，将逻辑补充完整。

3. ###### hook 断点逻辑的移植

async-debug的hook断点逻辑还是最早之前的版本，需要把osgdb的hook逻辑移植过来，不依赖硬编码解析rust，而是直接解析GDB输出。

4. 配置文件中的边界断点和hook断点名字太简略，导致自动设置断点时找不到具体的函数，只需要将实际的函数名写详细些：

```json
            "border_breakpoints": [
                { "function": "<taskctx::arch::riscv::TrapFrame>::user_return" ,"direction": "kernel_to_user"},
                { "function": "syscall::trap::handle_syscall::{async_fn#0}" ,"direction": "user_to_kernel"}
            ],
            "hook_breakpoints": [
                {
                    "breakpoint": { "function": "syscall::syscall_task::imp::task::syscall_exec::{async_fn#0}" },
                    "behavior": {
                        "functionArguments": "name",
                        "functionBody": "const p = await this.getStringVariable('name'); return p || 'user';",
                        "isAsync": true
                    }
                }
            ],
```
