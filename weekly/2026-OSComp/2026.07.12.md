2. 尝试设计异步OS调试功能：

- 由于之前往async- debug中移植OS调试功能时，遗漏了异步树构建原始数据的获取路径，导致异步树构建失败，实现一下，就没问题了，接下来需要初步设计如何实现异步OS调试。

- 异步 OS 调试的核心矛盾：目前两个功能是互斥的

  ![image-20260712011158938](https://p.ipic.vip/0pwzfk.png)

问题就是当 OS 状态机切换 breakpoint group 时，会调用 break-delete 把所有当前断点删掉。Python 端通过 gdb.Breakpoint API 安装的 PollEntryBP/CallSiteBP 也会被一并删除，这意味着 PollEntryBP 在 kernel 里刚装上，一切换到 user 空间，就全没了。回来的时候也不会自动恢复。

---
最开始需要解决的核心问题：

  1. PollEntryBP/CallSiteBP 的持久化

	切换特权级时，Python 端安装的追踪断点需要存活下来，或者在切换回来时自动重建。

  2. 白名单的分组

	Kernel 的 poll 函数白名单和用户程序的 poll 函数白名单是不同的。_WHITELIST_EXACT 和 _WHITELIST_ADDR_MAP 需要按 breakpoint group 分开存储，切换时跟着换。

  3. 影子栈的连续性

	_TLS_STACK 现在只在一个地址空间里推入/弹出 CID。跨特权级时，影子栈是应该连在一起（一个树），还是分成两棵树？

  4. 跨空间函数之间的关联

	用户态的协程调了 read().await，内核 sys_read 处理这个请求。这两者之间怎么关联？

---

**初步思路**

我倾向于分两阶段实现：

1. 先构建两棵独立的树

	Kernel 和用户态各维护自己的影子栈和异步树。切换时不混在一起。实现起来简单。

2. 然后再跨特权级关联

	在 syscall 边界处插入关联节点，把两棵树连起来。这个需要从 Border/Hook 机制获取 "当前正在穿越 syscall" 的上下文，在影子栈里插入一个 type: "boundary" 的节点。
